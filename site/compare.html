Where a limit can live

Tracing tools show what a run cost. Gateways sit between your code and the provider. AgentGuard runs inside the agent and refuses the next call once a limit is reached. They answer different questions, and they work together.

01

Four places

WhereExamplesWhat it can stopWhat it misses
Provider spend limitsSet in the OpenAI or Anthropic consoleSpend across the account or projectCannot tell one looping run from normal traffic
Gateway or proxyPortkey, LiteLLM proxyRate and budget limits on the traffic it routesSees model requests, not the agent's tool calls or retries. Adds a network hop
TracingLangSmith, LangfuseNothing by itself. It records what happenedShows you the loop after it ran
AgentGuard47This SDK, in your processThe next instrumented call once a spend, call, loop, retry, or time limit is reachedCalls that skip instrumented code. Not an invoice cap
02

A $5 limit in code

Patch the client once and pass the guard.

from agentguard import BudgetGuard, Tracer, patch_openai

patch_openai(Tracer(), budget_guard=BudgetGuard(max_cost_usd=5.00, warn_at_pct=0.8))
# Chat Completions calls now count toward $5. A warning is recorded at $4.
# The call that crosses $5 raises BudgetExceeded when it returns,
# and nothing after it is sent.

Checked against the real OpenAI client: with $1.50 calls, the fourth call returns, records $6.00, and raises. A fifth is never sent. Every tested path.
